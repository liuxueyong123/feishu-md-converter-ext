# ADR-0001：使用本地客户端事务修复 Lark Markdown 导入结果

## 状态

已接受

## 日期

2026-08-27

## 背景

国际版 Lark 导入本地 Markdown 后不会自动加粗表格第一行，并会把 Mermaid 保留为普通代码块。目标是在用户完成上传后，通过一次明确的扩展操作原地修复当前文档，同时避免服务端凭据、全站长期权限、遥测和逐项人工点击。

关键约束如下：

- 文档采用虚拟滚动，未显示区域的 DOM 不会持续存在；长代码块在 DOM 中还可能只保留中间片段。
- Lark 原生文本绘图运行在动态的 `*.larksuitepkg.com` 跨域 iframe 中。
- Lark OpenAPI 没有覆盖本需求所需的原生文本绘图创建和展示模式操作。
- DOM 菜单点击依赖可信鼠标事件，逐项执行速度慢且易受界面变化影响。
- Mermaid 迁移具有破坏性，只有新组件写入、渲染和“仅展示图表”校验成功后才能删除源代码块。

## 决策

采用 Manifest V3 本地扩展，并将实现分成三个权限边界：

1. 内容脚本使用 `activeTab` 扫描虚拟文档、显示 Shadow DOM 预览面板并编排任务。
2. 主页面脚本通过 Lark 编辑器已有的 `blockManager.applyTransaction` 创建、格式化和删除块。表头使用原生 `setAttributes` changeset，文本绘图使用 Lark 自身的 ISV block 类型。
3. 后台脚本只在用户选中 Mermaid 后请求 `https://*.larksuitepkg.com/*` 可选权限，并在对应 iframe 主世界中发送 Lark 组件自己的 `Record_setRecord` 消息。

Mermaid 采用两阶段迁移：按父块内索引倒序批量创建全部文本绘图和配套空文本块；扫描阶段通过 Lark 记录读取完整代码源码，避免 DOM 虚拟化截断；统一写入并校验 SVG、错误状态和 chart-only 模式，对尚未加载的跨域 iframe 将对应组件滚动到可视区后重试。成功项删除源代码块，失败项删除新组件并保留源代码块；若源块删除失败，则保留源块和已验证图表，优先避免数据丢失。

候选面板正文支持定位：点击候选项会按扫描时记录的滚动位置激活对应虚拟块，再使用稳定的 `data-record-id` 精确滚动并短暂高亮；复选框仅负责选择状态，避免定位操作意外改变批处理范围。

所有跨边界消息使用 allowlist 和大小上限验证。后台仅接受受支持 Lark URL 的主文档帧消息；单批最多 100 项，单段源码最多 1,000,000 个 UTF-16 代码单元，总源码最多 5,000,000 个代码单元。

## 考虑过的替代方案

### Lark OpenAPI

优点是接口相对稳定并且不依赖页面 DOM。缺点是需要应用、授权和凭据管理，而且当前不能完整表达文本绘图组件的创建、Mermaid 写入和 chart-only 展示模式，因此不采用。

### 模拟菜单、粘贴和鼠标点击

优点是接近人工操作。缺点是富文本编辑器依赖可信输入事件，虚拟滚动下需要逐项等待并容易误点；批量性能和可恢复性也较差，因此不采用。

### 使用 `debugger` 权限控制所有 iframe

优点是能直接进入跨域执行上下文。缺点是权限过大、安装提示敏感且会干扰开发者工具，不符合最小权限原则，因此不采用。

### 导出、转换并重新导入整篇文档

优点是 Markdown 解析完全可控。缺点是容易丢失 Lark 文档中的评论、协作历史和其他原生块，并且无法做到原地局部修复，因此不采用。

## 后果

- 用户安装时只看到低敏感度的 `activeTab` 与 `scripting`；文本绘图域名权限在实际使用 Mermaid 功能时单独征得同意。
- 不需要任何后端服务、秘密或 Lark OpenAPI 配置，文档内容不会离开当前标签页。
- 失败路径默认保留源内容并回滚新块，降低数据丢失风险。
- 实现依赖 Lark 未公开的 DOM、客户端事务结构、文本绘图 block 类型和 iframe 消息协议。Lark 更新后必须通过真实文档回归测试重新验证。
- 新增图类型、表格结构或其他 Markdown 修复功能时，应继续复用扫描、候选预览和两阶段提交边界，不能绕过校验直接删除源内容。
