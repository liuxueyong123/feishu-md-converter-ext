# 电子表格转文档表格实现计划

> 执行方式：使用 `superpowers:executing-plans`，在当前功能分支逐步实现；最终进行独立代码审查。用户已确认方案及继续实现，本轮不额外提交新功能。

**目标**：扫描嵌入式电子表格，允许用户勾选转换为可编辑的原生文档表格。

**设计依据**：用户在本次会话确认的简短设计：保留文字、换行、空单元格和列宽比例；首行加粗、浅灰底色；新表逐格校验成功后才移除原表；公式、图片等不能无损转换的内容保留并提示。

**架构**：内容脚本复用虚拟滚动扫描、候选面板和逐项修复流程。主世界适配器读取 Lark 页面已有的电子表格模型，通过已有原生事务创建 `table`、`table_cell` 和 `text` 记录，不请求外部 API。纯数据验证与记录创建独立于页面适配器。

**技术栈**：TypeScript、Chrome MV3、Vitest/jsdom、esbuild，无新增依赖。

## 全局约束

- 当前提交基线为 `4c285eb`，保留既有表头、Mermaid 和标题空行行为。
- 不读取凭据，不发外部请求，不根据 Canvas 截图或可见文本推断完整内容。
- 支持矩形文字数据；公式、富文本链接、合并单元格、图片、图表等不能完整保留的内容须明确拒绝转换。
- 限制单表规模及文本总量；无法读取或模型未加载时保留原表，提供可重试错误。
- 校验当前源数据未变更才删除源块；删除失败保留源与新表，避免丢失内容。
- 本轮日常验证使用相关测试与构建；type-check / lint 留待下次提交前执行。

## 审查重点

- 空单元格、换行与中文不能被 trim 或遗漏。
- 虚拟滚动结束后源块 DOM 已卸载，仍需能读到已加载模型或重新定位。
- 公式、合并、富文本、图片与其他非文字内容不能静默丢失。
- 协作编辑发生在扫描后或校验前时，不能删除变化后的源表。
- 新建、校验、删除和回滚失败均需有明确结果，重试不能误删原内容。
